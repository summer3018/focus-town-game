# ちいさな集中タウン（仮） / focus-town-game

**がんばった時間が、街になる。**

集中した時間のぶんだけスターがたまり、小さな街が少しずつ育つ、スマートフォン向けWebゲームです。
これは **市場検証用のMVP** で、将来的なiOS・Androidアプリ化を見据えた試作品です。

- サーバー・データベース不要／アカウント登録不要
- 広告・課金なし／有料API不使用
- データはすべて端末のブラウザ（localStorage）の中だけに保存

---

## 0. スマホで遊ぶ（圏外でもOK）

公開先： **https://summer3018.github.io/focus-town-game/**

1. スマホのブラウザで上のURLを開く（ここだけは通信が必要）
2. 共有メニューから **「ホーム画面に追加」**
   - iPhone（Safari）：共有ボタン → ホーム画面に追加
   - Android（Chrome）：右上の︙ → ホーム画面に追加 / アプリをインストール
3. 以後はホーム画面のアイコンから起動。**圏外・機内モードでもそのまま遊べます**

一度開いた時点で、ページ・スクリプト・アイコンすべてが端末内にキャッシュされます（Service Worker）。
セーブデータとプレイログは元々 localStorage なので、オフラインでも集中タイマー・街づくり・ミニゲーム・アンケート・JSON書き出しが全部動きます。

更新したいときは、通信がある状態でアプリを開き直してください。新しい版があれば自動で取り込まれます。

## 2. 遊び方

1. タイトルで「はじめる」
2. 「集中をはじめる」→ 時間を選ぶ（5／15／25分、または1〜60分のカスタム）
3. タイマーが動いている間は、**画面を閉じて目の前の作業をする**
4. 時間になるとスターがもらえる
5. 街の空いている区画をタップして、家・お店・公園を建てる
6. 建てた建物をタップするとレベルを上げられる（レベル3まで）
7. 休憩したいときは1分のミニゲーム「スターキャッチ」

### ゲーム内バランス（初期値）

調整値はすべて `src/core/config.ts` にまとめてあります。

| 集中時間 | 獲得スター |
| --- | --- |
| 5分 | 10★ |
| 15分 | 30★ |
| 25分 | 50★ |
| カスタム | 1分につき2★ |

| 建物 | 建設 | Lv2へ | Lv3へ |
| --- | --- | --- | --- |
| 小さな家 | 20★ | 30★ | 60★ |
| 小さなお店 | 30★ | 45★ | 90★ |
| 公園 | 20★ | 30★ | 60★ |

区画は6マス（固定位置）です。

## 3. 設計の要点

### タイマーは「実時刻」で数える

描画フレーム数は一切使っていません。集中を開始した時刻（`startedAt`）と終了予定時刻（`endsAt`）だけを保存し、
表示するたびに現在時刻から残り時間を計算します（`src/core/timer.ts`）。

そのため次のどれでも、戻ったときに正しい残り時間が出ます。

- ブラウザをバックグラウンドに送った
- 画面をロックした
- ページを再読み込みした
- ブラウザを完全に閉じて、あとから開き直した

ブラウザを閉じている間にタイマーが終わっていた場合は、**次に開いたときに完了画面から再開** します。

### 報酬の二重受け取りを防ぐ

集中セッションには一意のIDがあり、報酬を受け取ったIDは `claimedSessionIds` に保存します（直近100件）。
`claimReward()` はこのIDをすでに持っていれば `null` を返すため、

- 完了処理が何度呼ばれても
- 再読み込みしても
- 画面を行き来しても

スターは一度しか増えません（`tests/rewards.test.ts` / `tests/state.test.ts` で検証）。

中断した場合は報酬なしですが、責めるメッセージは出さず「いつでも、またはじめられます」とだけ表示します。

### ミニゲームと街づくりの分離

スターキャッチのスコアは **街づくりのスターには一切変換されません**。
街は集中した時間だけで育ちます。ミニゲームを繰り返すことが資源獲得の近道にならない設計です。

また、連打が最適解にならないよう次の工夫をしています。

- 何も無い所を叩くとコンボが切れる
- 星の出現位置は直前の位置から一定以上離れる
- 時間が進むほど表示時間が短く、出現間隔も短くなる
- 小さい星は得点が高いが表示時間が短い

### 保存データの修復

`normalizeSave()` が、壊れた・足りない・不正な値をすべて安全な値に直します（`src/core/storage.ts`）。
JSONとして読めないほど壊れていた場合は、元データを `focus-town:save:v1:broken` に退避してから作り直します。
`localStorage` が使えない環境（プライベートモード等）では、メモリ上の代替保存に自動で切り替わるため、起動自体は失敗しません。

## 4. 市場検証用の記録

### 記録するイベント

`game_start` / `focus_start` / `focus_complete` / `focus_cancel` / `reward_claim` /
`building_construct` / `building_upgrade` / `minigame_start` / `minigame_complete` / `return_visit`

各イベントに、発生時刻・匿名のローカル識別子・集中予定時間・経過時間・獲得スター・消費スター・建物の種類・ミニゲームスコアなどを必要に応じて付けます。

### 書き出し

「プレイ記録」または「設定」画面の **記録をJSONで書き出す** から、集計・アンケート回答・イベント一覧をまとめた
`focus-town-log_YYYY-MM-DD_HH-MM.json` をダウンロードできます。

### 集めないもの

個人情報・位置情報・連絡先・メールアドレス・広告IDは **一切収集しません**。
匿名のローカル識別子（`p_xxxx`）は端末内で生成した乱数で、外部に送信されることはありません。

### 制約（重要）

- **localStorage のみでは、全プレイヤーのデータを自動集計できません。** 記録は各プレイヤーの端末の中にしかありません。
  検証時は、テスターにJSONを書き出して送ってもらう運用が必要です。
- ログは **500件** で上限を設け、超えた分は古いものから消えます（容量の暴走を防ぐため）。
- ブラウザのデータを消すと記録も消えます。端末をまたいだ同期はありません。
- **端末の時刻を変更する不正への対策はMVPの対象外です。** 時計を進めれば報酬を早く得られます（市場検証の目的上、許容しています）。
- **ブラウザを閉じている間に通知を届けることはできません。** プッシュ通知は実装していません。タイマーの完了は「次にアプリを開いたとき」に反映されます。

## 5. アンケート

初回の集中完了後、または最初の建物を建てたあとに、一度だけ任意のアンケートを表示します（「あとにする」で閉じられます）。
「プレイ記録」画面からいつでも開けます。回答はlocalStorageに保存され、JSON書き出しに含まれます。

1. 集中時間で街が育つ仕組みは面白いですか？（5段階）
2. またこのアプリを使いたいですか？（はい／いいえ）
3. 街づくりとミニゲームのどちらが楽しいですか？
4. 集中タイマーとして使いやすいですか？（5段階）
5. 改善してほしい点はありますか？（自由入力）

## 6. 技術構成

- TypeScript + Vite（フレームワークなし・ランタイム依存ゼロ）
- 街とミニゲームの描画は Canvas 2D
- 街は論理解像度 180×210 で描いて拡大（`image-rendering: pixelated`）することでドット絵風にしている
- 効果音は Web Audio API のオシレーターで生成（外部音源なし＝商用利用の権利問題なし）
- 自動再生制限に合わせ、最初のタップまで `AudioContext` を作らない
- テストは Vitest
- オフライン対応は手書きの Service Worker（`vite-plugin-sw.ts` がビルド時に `sw.js` を生成）。workbox などは使っていない
- ホーム画面アイコンは `scripts/make-icons.mjs` が Node の zlib だけで PNG を生成（画像ライブラリ不要）

```
src/
  core/        ルール（画面に依存しない・テスト対象）
    config.ts         バランス設定値はすべてここ
    timer.ts          実時刻ベースのタイマー計算
    rewards.ts        報酬計算と二重受け取り防止
    buildings.ts      建設・強化のルール
    storage.ts        保存・読み込み・修復
    analytics.ts      プレイログとJSON書き出し
    minigameLogic.ts  スターキャッチのルール
    state.ts          状態の持ち主（画面はここ経由でのみ変更）
    audio.ts          効果音
  render/      街の描画
  ui/          画面の配線
tests/         自動テスト
```

## 9. 未解決の問題・今後の課題

- 街の建物が隣の区画と少し重なって見えることがある（奥の建物が手前に隠れる）。描画順は奥から手前で正しいが、Lv3の建物は横幅が大きい。
- ミニゲーム中にブラウザをバックグラウンドにすると、`requestAnimationFrame` が止まるぶん実時間より短く進む（集中タイマーと違い、ミニゲームは実時刻基準にしていない）。
- 効果音の音量バランスは未調整。実機で聞くと印象が変わる可能性がある。
- 端末時刻を変更する不正への対策なし（MVPの対象外）。
- 記録を全プレイヤーぶん自動で集める仕組みがない（JSONの手渡し運用）。
- 建物3種類・6区画のみ。長期の目標（街の完成）がまだない。

## 10. アプリ化（iOS / Android）の拡張方針

今回はスマートフォン向けWebゲームとしての完成を最優先しています。アプリ化する場合の方針だけ記しておきます。

1. **PWA化 → 完了済み**
   `manifest.webmanifest` と Service Worker を入れたので、ホーム画面に追加して全画面・オフラインで遊べます。
   ストア審査が不要なので、市場検証はこのまま進められます。

2. **Capacitor でネイティブ化**（ストア配信が必要になったら）
   今の構成（静的ファイルのみ・ネイティブ依存なし）はそのまま `npx cap add ios / android` でラップできます。
   このとき足せるもの：
   - **ローカル通知**（`@capacitor/local-notifications`）：集中終了をブラウザを閉じていても知らせる。今のWeb版で唯一できていない部分。
   - **保存先の置き換え**：`src/core/storage.ts` の `StorageLike` を差し替えるだけで Preferences / SQLite に移せる設計にしてある。
   - **バックグラウンド復帰の扱い**：タイマーが実時刻ベースなので、ネイティブでもそのまま動く。

3. **収益化を考えるなら**
   広告より「街の見た目の追加（建物の種類・季節・テーマ）」の買い切りが、このゲームの体験（集中のごほうび）と相性が良い想定です。
   ただし **市場検証の結果（アンケートQ2の再利用意向と、return_visit の数）を見てから** 判断する前提です。
