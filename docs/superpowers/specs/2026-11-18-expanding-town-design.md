# 広がる街（A）の設計

## 目的と理由
今の街は6区画・3種類・Lv3までで、毎日1〜2回の集中なら1〜2週間でやることがなくなる。
市場検証で「長く（何週間も）続けてくれるか」と「毎日開いてくれるか」を見たいので、
まず A「街が広がる」で終わりをなくし、そのあと B「住人のお願い」で毎日開く理由を足す（B は別の設計）。

テーマは **田舎の町が、だんだん都会になっていく**。

## 目標
- 区画を星で買い足して、ひとつの街が上限なく外へ広がる。
- 区画の数が節目に届くたびに、新しい建物と街の呼び名が解放され、それが遊び続ける目標になる。
- 大きくなった街を、指2本の拡大・縮小と指1本のスクロールで見て回れる。

## やらないこと（このAでは）
- B「住人のお願い」。
- 街の大きさの上限・「完成」。
- 描画ライブラリ（PixiJS など）の導入。
- 通知・サーバー・課金。

## 失敗とみなすこと（動いても駄目）
- 集中以外の方法で星が増える（ミニゲームの得点を星に変える、など）。
- 今遊んでいる人の街・星が消える、または変わる。
- スマホで区画が小さすぎて押せない、押したつもりで別の区画が選ばれる。
- 圏外で遊べなくなる（Service Worker の対象から新しいファイルが漏れる）。

## 制約
- 既存の構成のまま：TypeScript / Vite / Canvas 2D / localStorage / PWA。新しい依存は入れない。
- 調整値はすべて `src/core/config.ts` に置く。
- ゲームの決まり（土地・建物・節目）は純粋関数として `src/core` に置き、描画（`src/render`）と分ける。将来、描画だけ差し替えられるようにするため。

## 検討した作り方
1. **今の Canvas 描画を広げる（採用）**：カメラ（拡大・縮小・スクロール）、画面内だけ描く処理、座標で覚える区画を足す。依存なし、既存の絵と演出をそのまま使え、オフライン動作も保てる。数千区画では重くなるが、星の獲得量から何年も届かない。
2. PixiJS に乗り換える：大きな街でも軽いが、絵と演出を全部作り直し、読み込むファイルも増える。
3. 区画を DOM 要素で並べる：タップ判定は楽だが、今の絵と見た目が混ざり、数が増えると重い。

## 決めたこと（佐俣が決めた）
- 広がり方は「ひとつの街が大きくなる」（土地ごとの切り替えではない）。
- 区画は **空き地をタップして星で買う**。どこを買うかは自分で選ぶ。
- 街に上限はない。
- 建物の並びと解放の順番は下の表のとおり。

| 区画の数 | 街の呼び名 | 新しく建てられる建物 |
| --- | --- | --- |
| 最初（6） | 小さな村 | 家・お店・公園（今と同じ） |
| 12 | 村 | 田んぼ・畑 |
| 20 | 小さな町 | 郵便局 |
| 30 | 町 | 学校 |
| 45 | にぎやかな町 | 駅 |
| 65 | 市 | 商店街 |
| 90 | 都市 | ビル |
| 120 | 大都市 | 電波塔 |

- 星は集中した時間だけで貯まる（今と同じ）。

## 決めたこと（Claude の判断。佐俣が直してよい）

### 区画と座標
- 区画は整数の座標 `(x, y)` で表し、キーは文字列 `"x,y"`。今の区画 `slot` は `(slot % 3, Math.floor(slot / 3))` に対応させる（`0,0`〜`2,1`）。座標は負にもなる。
- 持っている土地は `land: string[]`（キーの配列）、建物は `buildings: Record<string, PlacedBuilding>` で持つ。
- **買える土地** = 持っていない座標のうち、持っている土地に上下左右で接しているもの。

### 土地の値段
- `値段 = min(LAND_COST.max, LAND_COST.base + LAND_COST.step × これまでに買った数)`。
- 初期値は `base 15 / step 5 / max 60`。1回目の購入（7区画目）が15★、10回目の購入（16区画目）で60★に届き、そのあとは一定。（Claude の判断：式を正とする）

### 節目
- 区画の数（`land.length`）が表のしきい値以上になったら、その行の建物と呼び名を解放。
- 解放した瞬間に、お祝いの演出と「〇〇が建てられるようになりました」の表示を出す。
- 建物を選ぶ画面では、まだ解放されていない建物も鍵つきで1つ先まで見せ、「あと〇区画で解放」と表示する。
- 今の `townTitle()`（建物レベルの合計で呼び名を決める）は、この区画の数による呼び名に置き換える。

### 新しい建物の値段（仮。あとで調整）

| 建物 | 建設 | Lv2へ | Lv3へ |
| --- | --- | --- | --- |
| 田んぼ・畑 | 25★ | 35★ | 70★ |
| 郵便局 | 40★ | 60★ | 120★ |
| 学校 | 60★ | 90★ | 180★ |
| 駅 | 80★ | 120★ | 240★ |
| 商店街 | 100★ | 150★ | 300★ |
| ビル | 140★ | 210★ | 420★ |
| 電波塔 | 200★ | 300★ | 600★ |

- 各建物はLv3まで、レベルごとに見た目が変わる（今と同じ考え方）。絵は今と同じく `src/render/sprites.ts` でコードで描くドット絵。
- 1区画に1軒。大きな建物も1区画に収める（複数区画をまたぐ建物は作らない）。

### カメラと操作
- 指1本のドラッグでスクロール、指2本でつまむと拡大・縮小。PCはマウスのドラッグとホイール。
- 指が 8px 以上動いたらドラッグ扱いで、タップとして扱わない。
- **区画の大きさは、ひし形の横幅（CSS px）で測る。** ひし形は横:縦 = 2:1 なので、横幅 56px のとき縦は 28px。
- 拡大の範囲は、区画の横幅がおよそ 32〜160 CSS px。
- **区画の横幅が 56 CSS px（縦 28px）より小さいときのタップは、選択せず、その場所に寄って横幅 56px 以上まで拡大する。** 押し間違いを防ぐため。
- 起動時は、持っている土地全体が収まる位置と倍率で表示する。ただし区画の横幅は 56px 以上を保ち、全体が収まらないときは、持っている土地の外枠の中心を画面の中心にする。
- 画面に映っている区画だけを描く。
- 買える土地は、薄い枠と小さな「売地」の印で見せる。タップすると値段つきの購入画面を開く。
- タイトル画面の小さな街も同じ描画を使い、街全体を収めて表示する（操作はしない）。

### 保存データ
- `SAVE_VERSION` を 2 に上げる。v1 のデータを読んだら、`land` を最初の6区画にして、`buildings` を座標キーに移す。星・記録はそのまま。
- 新規の人は最初の6区画を持った状態で始まる（30★は今と同じ）。
- `normalizeSave` は、知らない建物の種類・不正な座標・持っていない土地の上の建物を捨てる。
- 買った土地の数を数えるため `landPurchases: number` を持つ。

### 記録（分析用）
- イベント `land_purchase` を足す（値段・区画の数・座標）。
- 建物のイベントの `slot` は座標キー `cell` に変える。書き出しの要約にも `landCount` を足す。

## 作る人に任せること
- カメラの慣性（指を離したあと少し流れる）の有無と強さ。
- 各建物の絵の具体的なデザイン（テーマ「田舎→都会」に沿う、Lv3 は今の建物と同じくらいの大きさ）。
- 地面の描き方（芝・道など）と、買える土地の印の見た目。
- 区画の描画順（奥から手前）や、画面外判定の細かい作り。
- テストの細かい分け方。

## 確かめ方
- 自動テスト：土地の値段と上限、買える土地の判定、節目の解放、v1→v2 の移行、二重購入の防止、星が足りないときに減らないこと。
- 型チェック・ビルドが通ること。
- スマホ実機で、拡大・縮小・スクロール・タップの手ざわりを佐俣が確かめる（PC では判断できない）。
